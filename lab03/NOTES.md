git diff показывает разницу между двумя состояниями (рабочей папкой, индексом, коммитами). Отвечает на вопрос «что изменилось».

git show показывает один коммит целиком — его метаданные и diff относительно родителя.

git log показывает список коммитов (историю), без diff-а по умолчанию.

git log -S"def" нашёл коммиты, в которых добавлялось или удалялось вхождение строки "def" — то есть когда появлялись/менялись определения функций.

git blame показал построчно, какой коммит и какой автор добавил каждую строку файла — удобно, чтобы найти, когда появилась конкретная строка.

it restore vs git restore --source=...

git restore lab03/calc.py возвращает файл к состоянию последнего коммита (HEAD). Все незакоммиченные правки в файле теряются.
git restore --source=HEAD~2 lab03/calc.py берёт версию файла из указанного коммита (HEAD~2 — два коммита назад) и кладёт её в рабочую папку. Это позволяет посмотреть/использовать старую версию.

Что произошло бы с моими правками

Незакоммиченные правки при `git restore` безвозвратно теряются — Git их нигде не сохраняет. Восстановить можно только то, что было закоммичено.

git revert vs git reset --hard

git revert HEAD создаёт новый коммит, который отменяет изменения указанного коммита. Старый коммит остаётся в истории.
git reset --hard HEAD~1 удаляет последний коммит из истории и откатывает рабочую папку. История переписывается.
revert` безопаснее в опубликованной истории: другие могли уже скачать старые коммиты. `reset --hard` перепишет историю, и у всех возникнет расхождение. `revert` же просто добавляет новый коммит — все могут спокойно подтянуть его.

Чем тег отличается от ветки

Тег — постоянное имя, привязанное к одному конкретному коммиту. Он не двигается. По нему находят версию через полгода.
Ветка — подвижный указатель на последний коммит ветки. При новых коммитах ветка автоматически сдвигается вперёд.
Теги используют для релизов (v1.0, v2.3), ветки — для параллельной разработки.
